# File_viewer 설계

- 작성일: 2026-11-04
- 위치: `D:\ADE_sub\src\File_viewer`
- 상태: 사용자 검토 대기

## 1. 무엇이고 왜 만드나

File_viewer는 **Herdr**(코딩 에이전트용 터미널 멀티플렉서, 이 PC는 0.9.5 Windows 네이티브판) 칸 안에서 쓰는 파일 보기 도구다. `D:\ADE_sub`는 Herdr용 도구 모음 저장소이고, easy_GIT에 이어 두 번째 도구다.

지금은 에이전트가 만들거나 고친 파일을 보려면 Herdr 밖으로 나가 다른 프로그램으로 열어야 한다. 사용자 말로 "굉장히 불편하다". File_viewer는 그 왕복을 없앤다. **에이전트 칸의 오른쪽 칸에 늘 켜 두고**, 코드·json·md를 그 자리에서 보고, HTML은 브라우저로 바로 띄운다. 사용자가 참고하는 모습은 Orca(stablyai/orca)의 파일 탐색기 + 편집기 탭이다.

## 2. 목표

1. **Herdr 칸 안에서 파일을 본다.** 코드(문법 색 강조), json, md, 그 밖의 텍스트 파일.
2. **트리 + 탭 배치** (사용자 선택, 모형 B). 왼쪽 파일 트리에서 고르면 오른쪽에 탭으로 열린다. 여러 파일을 탭으로 열어 두고 오간다.
3. **오른쪽 칸에 계속 켜 둔다** (사용자 요청). 에이전트가 파일을 바꾸면 열린 탭과 트리가 저절로 새로 고쳐진다. 다만 에이전트가 고친 파일로 화면을 옮겨 가지는 않는다(§6).
4. **칸 폭에 맞춰 배치가 바뀐다.** 사용자는 "조절 가능하게"를 원했다(§4.3).
5. **HTML은 바깥 브라우저로 연다** (사용자: "바깥으로 나가도 상관 없어").
6. **바깥 프로그램으로 넘기기.** 따로 창을 띄워 보고 싶을 때는 Windows 기본 프로그램(md면 사용자가 쓰는 Obsidian 등)으로 연다.
7. **우클릭 메뉴** (사용자 요청): 탐색기에서 열기, 경로 복사, 기본 프로그램으로 열기.
8. **간단한 수정과 저장.** 사용자: "수정은 거의 안 하지만 되면 좋다." 있으면 좋은 기능이고 핵심은 보기다.

## 3. 목표가 아닌 것

- 파일 만들기·지우기·이름 바꾸기·옮기기. 트리는 보기 전용이다. *(설계자 결정)*
- 파일 **내용** 검색(grep). 찾기는 파일 **이름**만 한다. *(설계자 결정)*
- 탭 두 개를 좌우로 나란히 띄우기. 사용자가 필요 없다고 했다. 나란히 보고 싶을 때는 바깥 뷰어를 쓴다.
- md를 브라우저용 HTML로 바꿔 보여주기. 따로 창이 필요하면 기본 프로그램(Obsidian 등)으로 연다. *(제안했지만 사용자 답으로 빠짐)*
- 이미지·PDF 미리보기. 터미널(conhost)에서는 그림을 그릴 수 없다.
- git 동작(stage, 커밋 등). easy_GIT이 맡는다.
- SVN 작업 폴더 지원. 사용자는 git 저장소에서만 쓴다. git 저장소가 아닌 폴더에서도 파일 보기는 되지만 `M`/`+` 표시와 흐림 처리는 없다. *(뒷부분은 설계자 결정)*
- 에이전트가 고친 파일로 화면을 옮겨 가기(트리를 펼쳐 고르고 탭을 여는 것). 사용자가 원하지 않는다. 읽던 화면을 빼앗지 않는다.
- 실행 중에 시작 폴더를 바꾸거나 시작 폴더 밖의 파일을 열기. 다른 폴더를 보려면 `File_viewer [경로]`로 새로 띄운다. *(설계자 결정)*
- md 안의 이미지 그리기. *(설계자 결정, §4.2)* — mermaid 는 2026-11-05 사용자 요청으로 글자 그림을 넣었다(§4.2).
- 껐다 켰을 때 열려 있던 탭 기억하기. *(설계자 결정)*

**실패로 보는 것**
- 보는 품질이 바깥 뷰어보다 떨어져서 결국 다시 바깥에서 여는 것. 사용자 말로는 "더 좋은 뷰어로 보려고" 나가게 되는 것.
- 저장하면서 파일을 망가뜨리는 것: 인코딩이 바뀌거나, 줄 끝(CRLF/LF)이 바뀌거나, 에이전트가 고친 내용을 모르고 덮어쓰는 것.
- 한글 경로나 한글 내용이 깨지는 것.
- `node_modules`, `.venv` 같은 큰 폴더 때문에 트리가 느려지거나 멈추는 것.

## 4. 화면

### 4.1 기본 배치: 트리 + 탭 (사용자 선택)

```
┌ 파일 ──────────────┐ [design.md] [config.json] [index.html ↗]
│▾ src               │┌──────────────────────────────────────┐
│  ▾ easy_GIT        ││ 1 {                                  │
│    pyproject.toml  ││ 2   "name": "easy-git",              │
│  ▸ File_viewer     ││ 3   "version": 2,                    │
│  config.json     M ││ 4   "panes": [ ... ]                 │
│  notes.md        + ││ 5 }                                  │
│  index.html        ││                                      │
│ .git        (흐림) ││                                      │
│ .venv       (흐림) ││                                      │
└────────────────────┘└──────────────────────────────────────┘
 / 찾기  Tab 다음 탭  w 탭 닫기  [ ] 트리 폭  t 트리  e 편집  o 열기  q 종료
```

- **왼쪽: 파일 트리.** 시작 폴더 아래 전부를 보여준다.
  - 숨기는 것은 없다. **`.git`과 `.gitignore`에 걸린 파일·폴더도 보이되 흐리게** 표시한다 (사용자 결정).
  - 폴더는 처음에 접혀 있다. 펼칠 때 그 폴더만 읽는다. 큰 폴더를 미리 다 읽지 않는다.
  - 바뀐 파일 표시: **git 상태 기준** (사용자 결정).
    - `M`: 마지막 git 커밋(HEAD) 이후 내용이 바뀐 파일. stage 여부는 가리지 않는다.
    - `+`: git이 아직 추적하지 않는 새 파일.
    - 표시는 git 커밋될 때까지 남는다. 파일을 열어 봐도 지워지지 않는다.
    - 접힌 폴더에도 "안에 바뀐 파일이 있다"는 표시를 올린다. 폴더 이름에 색을 입히거나 `•`를 붙인다.
    - git 상태는 git 명령으로 읽기만 한다. 에이전트가 동시에 git을 돌리므로 lock 파일을 만들지 않게 한다(`GIT_OPTIONAL_LOCKS=0`, easy_GIT과 같음).
- **오른쪽 위: 탭 줄.** 트리에서 파일을 고르면 탭으로 열린다. 이미 열려 있는 파일이면 그 탭으로 간다. HTML 탭에는 `↗` 표시를 붙인다.
- **오른쪽: 내용.** 고른 탭의 파일 내용.
- **맨 아래 한 줄:** 지금 쓸 수 있는 키 안내.

화면 모형(브라우저용)은 이 worktree의 `.superpowers\brainstorm\12417-1793773244\content\`에 있는 `layout.html`(A/B/C 비교, B 선택)과 `layout-width.html`(폭에 따른 배치)에 남아 있다. `.superpowers/`는 git에서 무시된다.

### 4.2 파일 종류별 보기 (사용자 확인)

| 종류 | 탭 안에서 | `o` 키 |
|---|---|---|
| 코드·설정·텍스트 | 원문 + 줄 번호 + 문법 색 강조 | 기본 프로그램 |
| json | 원문 + 줄 번호 + 색 강조 | 기본 프로그램 |
| md | 처음에는 **꾸민 모양**(제목·목록·표·코드 블록)으로 보여준다. `v`로 원문과 오간다. mermaid 블록은 코드 블록 바로 밑에 선·상자 글자로 그린 그림을 붙인다(꾸민 모양일 때만. PATH 의 `mermaid-ascii` 1.6.1 이상, flowchart·sequence·ER 만. 사용자 요청 2026-11-05). 이미지는 `[그림: 설명]` 글자로 보여준다. 그림까지 봐야 하면 `o`로 Obsidian에 넘기는 것이 정상 흐름이다 *(설계자 결정)* | 기본 프로그램 (예: Obsidian) |
| HTML | 원문 + 색 강조 | **늘 브라우저**. 기본 프로그램이 다른 것으로 잡혀 있어도 브라우저로 연다 *(설계자 결정)* |
| 이미지·PDF·바이너리 | "미리 볼 수 없는 파일 — `o`로 열기" 안내만 | 기본 프로그램 |

- 글자 인코딩: UTF-8과 CP949 파일을 모두 깨지지 않게 보여준다. 둘 다 아니면 깨진 글자를 대체 문자로 바꿔 보여주고, 그 탭은 편집할 수 없게 한다. *(설계자 결정)*

### 4.3 칸 폭에 따른 배치 (사용자 확인: "조절 가능하게")

| 칸 폭 | 배치 |
|---|---|
| 넓음 | 트리 + 탭 + 내용 (§4.1) |
| 좁음 | 트리를 저절로 숨기고 탭 + 내용이 칸 전체를 쓴다. `t`를 누르면 트리가 칸 전체에 뜨고, 파일을 고르면 다시 내용 화면으로 돌아온다 (easy_GIT 좁은 칸 방식과 같음) |

- Herdr에서 칸 폭을 바꾸면 실행 중에 그 자리에서 배치가 바뀐다.
- 넓을 때도 File_viewer 안에서 `[` `]`로 트리 폭을 줄이고 늘리며, `t`로 트리를 숨기거나 다시 띄운다.
- 넓음과 좁음을 가르는 폭은 만들면서 실제 화면을 보고 정한다.

### 4.4 키 (기본안, 설계자 결정)

| 키 | 동작 |
|---|---|
| ↑ ↓ / Enter | 트리 이동 / 파일 열기·폴더 펼치기 |
| `/` | 파일 이름으로 찾기 → 고르면 탭으로 열기 |
| Tab / Shift+Tab | 다음 / 이전 탭 |
| `w` | 탭 닫기 |
| `t` | 트리 숨기기·보이기 (좁을 때는 트리 화면 ↔ 내용 화면) |
| `[` `]` | 트리 폭 줄이기 / 늘리기 |
| `v` | md: 꾸민 모양 ↔ 원문 (easy_GIT의 `v` 보기 전환과 맞춤) |
| `o` | 기본 프로그램으로 열기 (HTML은 브라우저) |
| `e` / `Ctrl+E` | 편집 시작 (§5). 한글 입력 상태에서는 `e` 가 조합으로 먹혀 안 오므로 `Ctrl+E` 도 받는다 |
| `m` | 우클릭 메뉴를 키보드로 띄우기 (§4.5) |
| `q` | 종료 |

세부는 만드는 사람이 정해도 된다. 같은 Herdr 칸에서 easy_GIT과 번갈아 쓰므로 겹치는 동작은 같은 키를 쓰면 좋다.

### 4.5 마우스와 우클릭 메뉴 (사용자 요청)

- 트리 항목 클릭 = 열기, 탭 클릭 = 그 탭으로, 휠 = 스크롤.
- **트리에서 우클릭**하면 작은 메뉴가 뜬다.
  1. **탐색기에서 열기:** Windows 탐색기를 띄우고 그 파일을 선택해 둔다. 폴더면 그 폴더를 연다.
  2. **경로 복사:** 전체 경로(`D:\ADE_sub\docs\...`)를 Windows 클립보드에 넣는다. 한글 경로도 그대로 복사돼야 한다. *(설계자 결정: 전체 경로. 사용자에게 상대 경로가 낫다면 말해 달라고 해 두었다)*
  3. **기본 프로그램으로 열기:** `o` 키와 같다.
- 탭에서 우클릭해도 같은 메뉴가 그 탭의 파일 기준으로 뜬다. *(설계자 결정)*
- **위험:** Herdr 0.9.5 + conhost가 마우스 클릭, 특히 우클릭을 프로그램까지 넘겨주는지 아직 확인하지 않았다. 구현 맨 처음에 확인한다. 안 넘어오면 메뉴는 키보드(§4.4 메뉴 키)로만 쓰고, 그 결과를 사용자에게 알린다. 그래서 메뉴는 처음부터 키보드로도 띄울 수 있게 만든다.

## 5. 수정 (있으면 좋은 기능)

- `e`를 누르면 지금 탭이 편집 상태가 된다. `Ctrl+S`로 저장하고 `Esc`로 보기 상태로 돌아간다. 저장하지 않은 채 나가거나 탭을 닫으면 버릴지 묻는다. *(설계자 결정)*
- 편집 중인 탭은 자동으로 새로 고치지 않는다.
- 저장할 때 디스크의 파일이 편집을 시작한 뒤 바뀌었으면(에이전트가 고쳤으면) **덮어쓸지 먼저 묻는다.** 묻지 않고 덮어쓰지 않는다.
- 저장할 때 **원래 인코딩(UTF-8 / CP949, BOM 유무)과 줄 끝(CRLF / LF)을 그대로 지킨다.**
- 한글 IME 입력이 되어야 한다. Ctrl+V 붙여넣기에는 기대지 않는다(§7).
- md는 원문 상태에서만 편집한다.

## 6. 자동 새로 고침 (사용자 확인)

- 열려 있는 탭의 파일이 바뀌면 그 탭 내용을 새 내용으로 바꾼다. 보던 스크롤 위치는 가능한 한 유지한다.
- 열린 파일이 지워지면 탭을 닫지 않고 "지워진 파일"이라고 표시한다. *(설계자 결정)*
- 트리는 펼쳐 둔 폴더 안에서 파일이 생기거나 지워지면 따라 바뀐다. 펼침 상태와 선택 위치는 유지한다.
- `M`/`+` 표시(§4.1)도 git 상태가 바뀌면 따라 바뀐다. 접힌 폴더에 올리는 표시도 마찬가지다.
- **화면을 옮기지 않는다** (사용자 결정). 에이전트가 새 파일을 만들거나 다른 파일을 고쳐도 지금 탭, 트리 선택, 스크롤은 그대로 둔다. 새로 생긴 파일은 `+` 표시나 `/` 찾기로 사용자가 직접 연다.
- 에이전트가 동시에 파일을 쓰고 있어도 앱이 죽지 않는다. 읽다가 실패하면 이전 화면을 유지하고 다음 확인 때 다시 읽는다.

## 7. 시작하는 방법과 제약

- **시작 폴더:** 띄운 칸의 현재 폴더를 **그대로** 트리의 맨 위로 쓴다. easy_GIT과 달리 저장소 최상위로 올라가지 않는다 *(설계자 결정)*. 하위 폴더에서 띄워도 git 상태 표시는 그 폴더 아래 파일에 맞게 나온다. `File_viewer [경로]`로 직접 실행해도 똑같이 동작해야 한다. Herdr 없이 시험할 수 있어야 한다.
- **Herdr에서 여는 법:** 사용자는 에이전트 칸 **오른쪽 칸**에 늘 켜 둔다. 오른쪽 칸을 직접 열고 거기서 실행하면 된다. Herdr 설정(`%APPDATA%\herdr\config.toml`)의 `[[keys.command]]`로 오른쪽에 칸을 열며 실행할 수 있는지는 확인이 필요하다. 된다면 키 하나를 걸어 둔다. easy_GIT의 `prefix+alt+e`, lazygit의 `prefix+alt+g`와 겹치지 않게 한다.
- **따로 뜬 창(다른 모니터):** `File_viewer --follow`. Herdr 에서 포커스된 칸의 폴더로 시작하고, 1초마다 확인해 칸을 옮기면 트리 맨 위를 그 폴더로 바꾼다. 열린 탭은 그대로 둔다 *(설계자 결정)*. Herdr 키 `prefix+alt+shift+f` 가 `start` 로 새 창을 띄운다. 사용자 요청 2026-11-05.
- **OS:** Windows 11. Herdr는 Windows 기본 콘솔 창(conhost) 안에서 돈다. Windows Terminal은 없다. conhost에서도 색과 선이 깨지지 않아야 한다.
- **Herdr:** 0.9.5. custom command는 `cmd.exe /d /c`로 실행된다. 설정에 `host_cursor = "native"`가 들어 있다(IME 조합 위치용).
- **한글:** 경로와 내용의 한글이 깨지지 않아야 한다(UTF-8, CP949).
- **붙여넣기:** 이 환경(conhost + Herdr)에서는 Ctrl+V 붙여넣기가 안 된다는 보고가 있다. 어떤 기능도 붙여넣기에 기대지 않는다.
- **언어·라이브러리:** Python 3.12 + Textual 8.x *(설계자 결정: easy_GIT과 같게)*. Textual에 문법 강조 보기, md 보기, 편집 칸이 이미 들어 있다. 새 의존성은 꼭 필요할 때만 더한다.
- **저장소 구조 (설계자 결정, easy_GIT과 같게):**
  - 코드: `src/File_viewer/` 아래 별도 프로젝트(`pyproject.toml`, `uv.lock`). 패키지 이름은 `file_viewer`, 실행 명령은 `File_viewer`.
  - 테스트: `test/File_viewer/`
  - 문서: `docs/design/`
- easy_GIT 코드에 기대지 않는다. 두 도구는 따로 설치하고 따로 돈다.

## 8. 성공 기준

- 에이전트가 파일을 만들거나 고쳤을 때, Herdr 밖으로 나가지 않고 오른쪽 칸에서 바로 그 파일을 열어 읽을 수 있다.
- 코드·json은 색 강조와 줄 번호로, md는 꾸민 모양으로 읽힌다. 읽는 품질 때문에 바깥 뷰어로 나갈 일이 줄어든다.
- 여러 파일을 탭으로 열어 두고 오간다.
- 켜 둔 상태에서 에이전트가 파일을 고치면 열린 탭과 트리에 저절로 반영된다.
- 칸 폭을 바꾸면 §4.3대로 배치가 바뀐다.
- HTML 파일을 키 하나로 브라우저에서 연다.
- 우클릭(또는 메뉴 키)으로 탐색기 열기와 경로 복사가 된다.
- 고쳐 저장한 파일의 인코딩과 줄 끝이 그대로다.

## 9. 만드는 사람에게 맡기는 것

- 넓음/좁음을 가르는 폭, 트리 폭의 기본값과 조절 단위.
- 자동 새로 고침 방식(파일 감시 또는 주기적 확인)과 주기.
- 문법 강조 방식(Textual 편집 칸의 강조 / rich Syntax 등)과 지원 언어 범위.
- 아주 큰 파일(수십 MB, 한 줄이 아주 긴 파일)을 다루는 방식.
- 파일 이름 찾기(`/`)의 일치 방식(부분 일치, 퍼지 등).
- 클립보드에 넣는 방법, 탐색기·브라우저·기본 프로그램을 띄우는 방법.
- §4.4 키의 세부.
